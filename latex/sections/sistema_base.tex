    \subsection{Pruebas de carga}
    \label{sec:sistema_base_pruebas_de_baseline}

        La prueba de carga se realizo usando una tasa constante de 40 usuarios durante 240s (4 minutos).
        Cada usuario realiza un solo request, es decir se mantiene un throughput constante de 40 requests por segundo.
        No se realizo warm-up ni ramp para no ensuciar las metricas de promedios.
        Tampoco se realizaron recargas de saldo intermedias, se utilizo una carga inicial suficiente para cubrir toda la prueba.

        Adicionalmente, aprovechando que siendo este el sistema inicial no se plantea una comparativa, decidimos para ilustrar el formato de los gráficos y explicar los criterios compartidos entre todos los escenarios.

    \subsection{Pruebas de estrés}

        Tampoco se realizaron recargas de saldo intermedias y se mantuvo el mismo uso de endpoints para que los resultados sean comparables.

    \subsection{Resultados y conclusiones}
    \label{sec:sistema_base_resultados_y_conclusiones}

    Los resultados obtenidos del escenario de carga nos indican que podemos clasificar los endpoints en tres categorias lo que nos permitira simplificar nuestro analisis.
    Adicionalmente, los resultados del escenario de estres y resistencia nos indican que el sistema presenta una degradacion significativa por la mala genstion del log. Esta observacion motivara la propuesta 1.
    Finalmente, los resultados del escenario de caos nos indican que el sistema base no provee mecanismos de recuperacion. Esta observacion motivara la propuesta 2.
